# 從揭露書到可互動的排程引擎

本版依據使用者提供的「路徑規劃的方法和使用該方法的電子裝置」揭露書與原 repo 程式整合。SAW 是介面沿用的名稱；機制對應文件的 **sower 收割者**，不是 Simple Additive Weighting。文件原件沒有上傳到 repo。

## 來源與實作對照

| 文件構想 | 實作 | 說明 |
|---|---|---|
| 訂單權重兼顧路徑距離 | `weights`、`Objective.evaluate` | 保留原始公式比較模式，新增可解釋的營運 loss |
| 菁英順位過濾 | `repair` | 用二分圖匹配修復排列；無解時明確報錯，避免篩到空族群 |
| PMX、突變與菁英保留 | `pmx`、`evolve` | PMX 保證每筆訂單剛好一次；swap / inversion 後重新評分 |
| 多元宇宙與收割者 | `evolve` | 各世界獨立 RNG；每 K 代收集菁英、洗牌，發送到其他世界並取代尾部，保留本世界最佳 |
| 路徑長度 | `Costmap.astar`、`prepare` | A* 避牆後的真實網格路徑，無直線穿牆 |

原碼的 `sower_rate` 未實際使用，世界只做獨立重新啟動；突變物件沿用突變前的 `length`；每代多加一次 elites 導致族群數超標；小訂單數時交配切點範圍可為空；禁止順位使用一次性 `filter` 迭代器也可能漏查。新版獨立引擎修正這些問題，保留歷史 demo 供比較。

## Costmap 與 A*

每個像素是一個格子，座標 `(x,y)` 原點為左上角、x 向右、y 向下。黑色值小於等於 threshold 為障礙，白色 255 為最低成本；其他灰階是可通行的高成本區。透明像素視為黑色障礙。地圖邊界外視為障礙。

機器人 footprint 用 `ceil(radius / resolution)` 格的方形膨脹保守近似圓形，因此可能拒絕理論上勉強可過的門。UI 安全邊界與後端使用相同規則。8 鄰接 A* 使用 octile heuristic；對角移動只有兩個相鄰正交格都能通過時才允许。每條邊成本為步長乘兩端灰階倍率平均，倍率 `1 + gray_cost × (255−pixel)/255`，始終 ≥ 1，保證 heuristic 可採用下界。

所有節點對的 A* 每次任務只計算一次，再快取對稱路徑、幾何距離與加權成本。GA 只查表，不重跑 A*。UI 沿格子中心繪線，沒有抽稀後斜切障礙的問題。

`Dij` 是選定 A* 路徑的幾何距離（m）；因 A* 優化灰階成本，D 不一定是忽略成本的幾何最短距離。`Tij` 對該路徑積分：每步距離 × 灰階倍率 / 速度（s）。在目的地的 `local_radius` 範圍內使用 `min(cruise, order.speed)`，其他路段用巡航速度。因此 T 可不對稱；D 對稱。這是目的地附近速度近似，不是任意空間速度場的最短時間搜尋。

## 訂單權重與矩陣

對訂單 j，在排程開始時固定計算：

$$\sigma(z)=\frac{1}{1+e^{-z}},\qquad w_j=1+9\sigma(z_j)$$

$$z_j=b+a_I\frac{I_j}{10}+a_W\min(\frac{W_j}{P_j},3)+a_RR_j+a_D\min(\frac{d_{0j}}{50},3)+a_V\left(1-\frac{\min(v_j,v_0)}{v_0}\right)$$

預設 `(aI,aW,aR,aD,aV,b)=(2,2,2,1,1,−3)`。I ∈ [0,10] 是重要度，W 是已等待秒數，P 是耐久度秒數，R ∈ [0,1] 是使用者估計的棄單風險／損失係數，d 是起點到 j 的 A* 距離（m），v 是訂單附近速度（m/s），v0 是巡航速度。等待比例與距離比例截在 3，sigmoid 指數截在 ±60 以避免 overflow。固定基準 50m 讓加減訂單不會改變其他訂單的距離正規化基準。

W 矩陣的 **列是出發點 i、欄是目的地 j**。`Wij = wj`，對角線、起點與自訂終點的目的地欄為 0。UI 顯示 W、D、T 三張表，避免把重要度與旅行時間混成一個不可解釋的數字。W 是由每筆訂單參數產生的目的地重要度矩陣；本版不支援手動覆寫每個有向邊的 W 值。

## 營運 loss

$$L=T_{finish}+\lambda\frac{\sum_jw_jA_j}{\sum_jw_j}+\mu\sum_jR_j\frac{\max(0,W_j+A_j-P_j)}{P_j}+\nu D_{total}$$

A 是从本次開始到抵達該訂單的秒數，包含先前站點服務時間；完成時間包含最後站點服務時間及選擇的返航／終點行程。預設 λ=1、μ=120秒、ν=1秒/米，所以各項可視為秒數等價成本。UI 的改善百分比以原始訂單順序（若不符合順位限制則先修復）為基準，並非全域最優或與等算力其他方法比較。

耐久度是軟時間目標，不是硬 deadline。硬約束僅支援禁止的 1-based 配送順位；無硬 deadline、取送配對、電梯、載重容量或多機器人協作。風險係數不是經驗校準的棄單機率。

## 揭露書原始公式

文件圖片的公式為：

$$L_{disclosure}=\sum_{(i,j)}\sigma\left(\frac{d_{ij}}{10\,que_j\,(1+w_i+w_j)}\right)$$

程式原本 `TSP_GA.py` 實作其實不同：`d / [10 × (sigmoid((wi+wj)/5)+1) × que]`。本版「揭露書」模式按文件圖片公式實作，d 換成避牆 A* 距離，que 是 1-based 到訪順位；起點／終點的權重是 0。該式可能以延後昂貴邊來降低 loss，不能宣稱必然優先服務高權重訂單，因此營運模式才是預設。

## Sower、限制與可重現性

每個世界維持固定 population，前 10% 菁英保留，3-way tournament 選親代、PMX 交配、swap／inversion 突變。每條染色體使用 immutable tuple 作快取 key；最多保留 50,000 個評分結果。限制修復使用 augmenting-path 二分匹配，不能滿足的整體順位組合在進化前報錯。

每 interval 世代，收集各世界前 `max(1, floor(population × migration))` 條菁英，使用固定種子洗牌，向不同世界重新分配，替代尾部劣解，最後重排。migration=0 時不交換；SAW 關閉時只跑單世界。每代記錄各世界最佳解、路徑、配送時間表、多樣性與交換筆數。多世界在單一背景執行緒輪流推進世代，屬於邏輯平行，並非多核心並行運算。

GA 為啟發式，不保證全域最优或每次 SAW 都比單世界好；比較時要注意 SAW 使用更多候選評估。固定 seed 與相同輸入可以重現。相同座標的多筆訂單允許存在，距離為 0 但各自服務時間仍累加。
